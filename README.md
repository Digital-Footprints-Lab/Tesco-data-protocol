# Data Validation

1. Upon data collection, the research team should have received:
    1. A reference code from each participant
    2. A verification code from each participant
    3. An email sent from Tesco titled "Customer data request" that contains the link to download the data from each participant (it is likely that each request will result in multiple emails)

2. The research team should check that:
    1. The reference codes are in the correct format, which consists of 9-digit numbers
    2. The verification codes are in the correct format, which consists of 6-digit combinations of numbers and letters (they do _not_ have to have numbers and can have only letters)
    3. An email from Tesco was indeed received

# Data Preparation

1. Download the data. Importantly, name each .JSON file with the reference code of that data request. For instance, if the reference code was `123456789`, name the file `123456789.json`.

2. For the purpose of this document, all .JSON files downloaded from Tesco will be saved into a folder named `Raw`. An empty folder called `Alt` is also created to save the output files from the following data manipulations.

3. Below, the command line tool `jq` will be used to manipulate .JSON files. There are, of course, other tools to perform these operations, but that is beyond the scope of this documentation. See the official [download page](https://jqlang.github.io/jq/download/) to install `jq`.

4. The first step is to insert the reference codes into the .JSON files, so that they can be linked to other data sets generated by the participants (e.g., survey data). For instance, if the reference code was `123456789` and the data file was thus `123456789.json` inside the `Raw` folder, this operation will insert the field `"reference_code": 123456789` into the .JSON file and save it as `123456789_alt.json` into the `Alt` folder. The command line codes are:

```bash
for file in ./Raw/*.json; do

    filename=${file##*/}

    jq --argjson x "${filename%%.*}" '.reference_code+=$x' "${file}" > ./Alt/"${filename%%.*}"_alt.json

done
```

This operation will loop through all files inside the `Raw` folder. The first part of the one-liner (i.e., `jq --argjson x ...`) will pass the filename as an argument and insert it into the .JSON file, the second part (i.e., after the `>` operator) simply saves the output file as `*_alt.json` insider the `Alt` folder.

5. The second major step is to merge all .JSON files inside the `Alt` folder into one .JSON file. Specifically, the output will be a Newline Delimited .JSON file, that is, the data of each participant will be written as a new line.

```bash
jq -c . ./Alt/*.json | sed 's/\\"//g'| sed 's/\\r//g' |sed 's/\\\\/ /g' > ./merged.json
```

The first part of the one-liner (i.e., `jq -c ...`) will print each .JSON file in the `Alt` folder onto a new line, while the next few parts (i.e., `sed ...`) are ad-hoc solutions to handle some characters that can cause issues when importing the data into another ecosystem. Here the code will delete all instances of `\"` and `\r` because these patterns causes errors in PostgreSQL.

# Data Import 

## PostgreSQL

This section assumes a database has been set up to store the incoming data. Connect to the database via `psql`, `pgcli`, or other interfaces.

Below is an example of a SQL script that will reshape the data into a clean and two-dimensional format. For the sake of clarity, temporary tables will be used throughout, which need to be discarded every time the script is run in the same session (`DISCARD TEMP;`).

```sql
CREATE TEMP TABLE temp_data_import (col_jsonb jsonb);

\copy temp_data_import (col_jsonb) FROM './merged.json';

CREATE TEMP TABLE temp_data_by_customer AS
(
    SELECT
        col_jsonb -> 'reference_code' AS reference_code,
        col_jsonb -> 'Customer Profile And Contact Data' -> 'Clubcard Accounts' -> 'registered clubcard' AS clubcards, 
        col_jsonb -> 'Customer Profile And Contact Data' -> 'Clubcard Accounts' -> 'postal address' -> 'postcode' AS postcode, 
        col_jsonb -> 'Customer Profile And Contact Data' -> 'Online Accounts' -> 'title' AS title, 
        col_jsonb -> 'Purchase' -> 0  AS purchases
    FROM temp_data_import
);

CREATE TEMP TABLE temp_data_by_basket AS
(
    SELECT
        reference_code AS reference_code,
        jsonb_array_elements(purchases) AS basket
    FROM temp_data_by_customer
);

CREATE TEMP TABLE temp_data_by_item AS
(
    SELECT
        reference_code AS reference_code,
        basket -> 'timeStamp' AS time_stamp,
        jsonb_array_elements(basket -> 'product') AS item
    FROM temp_data_by_basket
);

CREATE TEMP TABLE temp_data_by_basket_clean AS
(
    SELECT
        reference_code AS reference_code,
        basket -> 'timeStamp' AS time_stamp,
        basket -> 'purchaseType' AS channel,
        basket -> 'basketValueGross' AS basket_value_gross,
        basket -> 'basketValueNet' AS basket_value_net,
        basket -> 'overallBasketSavings' AS basket_savings,
        basket -> 'storeId' AS store_id,
        basket -> 'storeAddress' AS store_address,
        basket -> 'storeName' AS store_name,
        basket -> 'storeFormat' AS store_format
    FROM temp_data_by_basket
);

CREATE TEMP TABLE temp_data_by_item_clean AS
(
    SELECT
        reference_code AS reference_code,
        time_stamp AS time_stamp,
        item -> 'name' AS name,
        item -> 'quantity' AS quantity,
        item -> 'price' AS price,
        item -> 'weightInGrams' AS weight,
        item -> 'volumeInLitres' AS volume
    FROM temp_data_by_item
);
```
